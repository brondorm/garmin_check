# KSC Search — поиск похожих багов

Внутренний инструмент команды: перед заведением нового бага пользователь
проверяет, нет ли уже похожего. Задаёт зону поиска фильтрами, описывает суть
проблемы своими словами и получает список наиболее похожих по смыслу багов.

Прототип реализует функциональное ТЗ первого этапа — одностраничный интерфейс
на русском языке в стиле современного бренд-бука Kaspersky.

## Как открыть

Бэкенда нет — это статический фронтенд. Достаточно открыть `index.html`
в браузере. Можно и через локальный сервер:

```bash
cd ksc-search
python3 -m http.server 8000
# затем http://localhost:8000
```

## Что внутри

- `index.html` — разметка экрана: фильтры → запрос → результаты.
- `styles.css` — оформление (тёмная тема, фирменный зелёный акцент Kaspersky).
- `app.js` — логика: фильтры, имитация запроса, рендер состояний.

## Реализованное по ТЗ

**Фильтры (все опциональны):**
- Итерация — мультивыбор галочками-чипсами (набор, не диапазон).
- Статус — категории «Открытые» / «Resolved» / «Закрытые» (мультивыбор).
- Тип Work Item — пока только `Bug`, список заложен на расширение.

**Запрос:** многострочное поле с примером-плейсхолдером; кнопка «Искать»
неактивна при пустом поле; `Ctrl/Cmd + Enter` запускает поиск.

**Результаты:** карточки, отсортированные по похожести (сверху — самые похожие):
степень похожести в процентах с цветовой индикацией (зелёный/жёлтый/серый),
кликабельный заголовок и ссылка на Work Item (открывается в новой вкладке),
тип WI, итерация, статус, версия продукта, фрагмент описания.

**Состояния:** загрузка (скелетоны), есть результаты (+счётчик «найдено N»),
пусто («Похожих багов не найдено»), ошибка («Не удалось выполнить поиск» +
кнопка «Повторить»).

## Данные-заглушка

Список багов захардкожен в `app.js` (`MOCK_BUGS`). Нажатие «Искать» имитирует
запрос к серверу с задержкой ~0.5–1 с и фильтрует заглушку на стороне клиента
с учётом выбранных фильтров (изредка имитируется сетевая ошибка — для проверки
состояния «Ошибка»).

Вся «сетевая» часть изолирована в функции `searchBugs()` — позже её заменят на
реальный API без переделки интерфейса. Набор полей карточки соответствует
будущему контракту API.

## Вне рамок этапа

Авторизация, создание/редактирование багов, реальные запросы к TFS, LLM-анализ
с вердиктом «дубликат / похоже / уникально» — сознательно не реализованы
(см. ТЗ, разделы 9–10).
